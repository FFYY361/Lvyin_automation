# 马杯比赛前瞻资料使用规则

## 1. 资料组成

写作资料分为三部分：

- `match_context`：本场比赛的赛事、阶段、时间、场地和双方顺序，是判断本场任务及正文顺序的
  依据；
- `manual_context`：人工维护的球队和球员描述，用于了解球队风格、阵容特点、年级、位置、
  伤病等系统无法可靠取得的信息；
- `automatic_context`：系统整理的排名、战绩、历史赛季、比赛摘要、首发和事件，用于了解
  可以由比赛数据直接支持的事实。

只能使用本次输入中明确给出的内容。资料没有说明的阵型、位置、伤病、缺席、人员关系和历史
背景不得猜测；缺少依据的内容直接省略。

`待补充`、`null` 和缺失字段都表示没有可用事实，不得将其改写成肯定或否定结论。空数组表示
在该数组规定的资料范围内没有记录。

## 2. 双方顺序与数据归属

`match_context` 中的主队对应正文第一段，客队对应正文第二段。`automatic_context.home_team`
和 `automatic_context.away_team` 始终沿用这一顺序。

马杯采用赛会制，`home`、`away`、主队和客队都只是区分双方、确定顺序和标记数据归属的技术
字段，不表示实际的主场或客场。正文不得将这些字段写成“坐镇主场”“客场作战”等主客场情境，
也不得据此推断场地熟悉度、旅途消耗、观众支持或其他优势。

单支球队的历史比赛以该球队为观察对象：

- `side` 表示该球队在那场比赛中是 `home` 还是 `away`；
- `self` 表示该球队；
- `opponent` 表示那场比赛的对手；
- `goals_for` 和 `goals_against` 分别表示该球队的进球和失球。

历史比赛中的 `side` 同样只用于识别数据归属，不应在正文中改写为主场或客场经历。

`head_to_head` 中的比赛已经统一为本场比赛的主客顺序。即使历史比赛的实际主客关系与本场
相反，球队数据、比分、首发和所有事件的归属也已经同步调换。因此，其中的 `home_team` 永远
指本场主队，`away_team` 永远指本场客队，不需要再次换算。

## 3. 当前赛事数据

`current_tournament.swiss_standing` 汇总本场之前的瑞士轮第一阶段比赛，所有球队统一比较积分，
不表示固定小组排名。它与 `group_standing` 分别适用于瑞士轮和传统小组赛。
`rank` 为 `null` 时必须遵守 `rank_note`，不得自行补算顺位、断言晋级或锁定淘汰赛对手。
人工球员描述只包含目标赛事该队的有效报名球员，往年球员资料仍保存在院系资料库中。

`current_tournament.group_standing` 只统计本场之前的小组赛，用于说明小组排名、积分和小组赛
战绩。`rank` 为 `null` 时表示无法可靠取得准确排名，具体原因见 `rank_note`，不得自行推算或
断言名次。

`current_tournament.record_before_match` 统计本届赛事截至本场之前的全部比赛，可能同时包含
小组赛和淘汰赛。它与 `group_standing` 的统计范围不同，不得将两者的场次和积分混为一谈。

`season_outcomes` 提供此前赛季已确认的最终成绩及来源。有本体排名的赛季只采用本体成绩；
本体无排名才选取前身最佳成绩，全部无排名则为“未参赛”。不得根据比赛数量推断参赛或最终名次。

`history_teams[].past_seasons` 分别统计实际球队在此前赛季的赛事级战绩，不表示合并本体的总战绩。

汇总字段由系统计算。优先直接使用给出的胜、平、负、积分和进失球，不要从比赛列表重新统计，
也不要根据部分事件反推整场或整届赛事的数据。

## 4. 比赛记录

`history_teams[].recent_matches` 保存近期比赛的比分、双方首发和完整有效事件。
`history_teams[].earlier_matches` 保存更早比赛摘要，没有事件字段不代表没有首发、换人或牌。

近期战绩、历史赛季统计和直接交锋只包含系统标记为数据录入完成的比赛；尚未完成录入的比赛
不会进入这些历史事实。

所有直接交锋均保存在 `head_to_head`，并提供事件层面的完整资料，不受近期比赛数量限制。若
`head_to_head` 为空，表示系统覆盖的历史范围内没有双方直接交锋。

`outcome` 是观察对象的官方胜负结果。单支球队历史比赛中 `result_type` 的含义如下：

- `normal`：正常赛果；
- `penalty_shootout`：通过点球大战决定胜负；
- `self_abandon`：观察对象被判负；
- `opponent_abandon`：对手被判负；
- `both_abandon`：双方均有弃权或判负记录。

直接交锋沿用本场主客队视角，因此其中以 `home_team_abandon` 和 `away_team_abandon` 分别表示
本场主队、本场客队在历史比赛中被判负；`both_abandon` 的含义不变。

弃权比赛中的 `goals_for` 和 `goals_against` 是官方判定比分，只能用于说明官方结果、排名和
积分，不能用于评价场上进攻、防守、控球或比赛过程。`awarded_wins` 和 `awarded_losses` 表示
汇总战绩中包含的判定胜负数量。

## 5. 首发和事件

`starting_lineups` 已从普通事件流中提取，分别列出双方有记录的首发姓名。首发名单可以用于
观察多场比赛中反复出现的人员，但不能仅凭首发记录推断球员的位置、阵型、伤病、停赛或主力
身份。某人没有出现在一场比赛中，也不能据此断言其缺席原因。

`goals` 记录进球方、时间、进球者和进球类型；进球者为 `null` 时不得猜测姓名。`normal`、
`penalty` 和 `own_goal` 分别表示普通进球、点球和乌龙球。

`substitutions` 按球队和时间整理换上、换下球员。`players_on` 与 `players_off` 是同一时刻的
名单；除非资料明确建立对应关系，不得把两个数组中的球员强行一一配对，也不得仅凭换人时间
推断具体战术意图。

`cards` 记录黄牌、两黄变红和红牌。`penalty_shootout` 单独记录点球大战结果和罚球事件，不与
普通进球重复计算。无法归入已知类别的有效事件保存在 `other_events`，只能按其明确字段使用。

## 6. 人名和资料取舍

人工描述、首发和事件中可能包含真实姓名。姓名可用于识别同一球员在多场比赛中的记录，但
正文如何处理姓名必须服从写作规则。不能因为某人多次进球或首发，就在没有人工描述支持时
为其补充场上位置、技术风格、年级或身份。

不要求在文章中覆盖全部资料。应优先选择能够说明球队近期状态、稳定特点、人员变化和本场
对位关系的事实，避免逐项复述比分、首发名单和事件流水。

当资料之间出现无法合理解释的冲突时，赛程和主客顺序以 `match_context` 为准，比赛结果、
统计和事件以 `automatic_context` 为准，球队及球员的定性描述以 `manual_context` 为准；仍然
无法确定的内容直接省略。

## 院系合并与历史身份

`history_teams` 按实际球队身份分别组织本体和前身，`is_predecessor` 标记前身身份。前身战绩只能
作为历史背景，不得改写为本体已经取得的战绩，也不得将不同前身的胜负相加成本体总战绩。

本届赛事战绩只属于本场对应的实际球队。当前赛季其他赛事的记录与此前赛季记录分开理解。
前身之间的比赛可以分别出现在各自历史中，不代表合并球队与自己交锋。

`head_to_head` 的两侧仍按本场双方顺序组织，名称是历史比赛当时的实际身份配置简称。
当前球队与历史身份的继承关系由 `history_teams` 明示，不要将历史名称统一替换成当前名称。
同一场比赛可能同时出现在不同身份的历史统计中，不得重复累计为合并球队战绩。
