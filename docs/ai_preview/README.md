# AI 前瞻：资料数据库与 Prompt 工程

本目录记录 AI 前瞻功能的资料库、Prompt 工程和本地生成评测。球队、球员、赛事和历史比赛
资料已迁移到 PostgreSQL；Prompt、赛制说明、写作规则和语料仍由 Git 管理。

## 当前目标

PostgreSQL 是运行时唯一资料来源。迁移使用的旧 Markdown/JSON 已删除；CLI、网站、查询、
战报和 Prompt 不会回退读取文件。

资料分为三类：

1. 人工资料：`institutions` 保存院系、历史球队 ID、三类球队描述和按姓名定位的球员描述。
2. 自动资料：`tournaments`、`games` 保存赛事、报名、比赛、事件和排名等信息。
3. 语料和规则：每篇优秀前瞻一个 Markdown 文档，暂不区分写作风格；根据语料人工总结
   通用正文规则、标题规则和禁用表达。

## 初版数据原则

- 球队和院系清单以数据库 `institutions` 为准。
- 球员清单以 25-26 赛季男足、女足、五人制全部有效报名球员为准，按院系归档。
- 每支球队的资料只有一个 `description: string`；可在其中写风格、打法、阵容特点等。
- 每名球员的资料只有一个 `description: string`；可在其中写年级、位置、球风、伤病等。
- 球员在单个院系文档内以姓名唯一识别，完整定位为“院系 + 姓名”；不把远端
  `player_id` 作为本地资料 ID。
- 不为描述拆分标签、有效期、来源、核验时间或其他结构化字段。
- 不在描述中重复系统可获取的球队战绩、球员进球、出场次数和出场时间。
- 管理员通过资料管理页面维护球队和球员描述。
- 标题中的球员姓名和球队类型只用于定位文档条目，不属于描述内容。
- 自动资料只保存可能用于前瞻的字段，不保存完整接口响应、手机号或其他无关数据。
- 入选 Schema 样例的安全字段和事件必须完整，不能只保留部分事件类型。
- automatic 同步从数据库读取赛事清单，完整抓取后以单事务更新数据库。
- 首版 Prompt 使用固定 System 规则和由程序生成的 User message；具体格式见 Prompt 文档。
- AI 输出只作为人工审核的草稿，不能自动发布。
