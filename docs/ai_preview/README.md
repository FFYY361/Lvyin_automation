# AI 前瞻：文档资料库与 Prompt 工程

本目录记录 AI 前瞻功能的前期设计。当前阶段只完成文档和方案，不实现网站、脚本或模型调用。

## 当前目标

先建立一个“人工 Markdown + 自动 JSON”的本地资料库。资料库框架和内容基本形成后，
再开展 Prompt 工程，并用约 5-10 场比赛进行初步人工验收。最后才讨论接入现有网站。

资料分为三类：

1. 人工资料：每个院系一个 Markdown 文档。文档内包含该院系男足、女足、
   五人制球队各自的一段描述，以及 25-26 赛季该院系所有报名球员各自的一段描述。
2. 自动资料：以 JSON 保存系统能够取得的赛事、比赛、比分、事件和排名等信息。
3. 语料和规则：每篇优秀前瞻一个 Markdown 文档，暂不区分写作风格；根据语料人工总结
   通用正文规则、标题规则和禁用表达。

## 初版数据原则

- 球队清单以 `src/thufootball/notes/teams.json` 为准。
- 球员清单以 25-26 赛季男足、女足、五人制全部有效报名球员为准，按院系归档。
- 每支球队的资料只有一个 `description: string`；可在其中写风格、打法、阵容特点等。
- 每名球员的资料只有一个 `description: string`；可在其中写年级、位置、球风、伤病等。
- 球员在单个院系文档内以姓名唯一识别，完整定位为“院系 + 姓名”；不把远端
  `player_id` 作为本地资料 ID。
- 不为描述拆分标签、有效期、来源、核验时间或其他结构化字段。
- 不在描述中重复系统可获取的球队战绩、球员进球、出场次数和出场时间。
- 所有描述由人工直接编辑 Markdown 文档并负责更新。
- 标题中的球员姓名和球队类型只用于定位文档条目，不属于描述内容。
- 自动资料只保存可能用于前瞻的字段，不保存完整接口响应、手机号或其他无关数据。
- 自动资料的快照粒度、刷新方式和字段格式在查看真实数据后再确定。
- Prompt 的组织、上下文和输出格式在资料库完成后再确定。
- AI 输出只作为人工审核的草稿，不能自动发布。
