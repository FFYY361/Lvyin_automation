# 本地资料库实施规划

## 1. 当前阶段

本地资料库基本完成后开始 Prompt 工程和生成质量验收。本文中的“资料库”指由 Markdown
和 JSON 文件组成的本地资料集合，当前不建设网站，也暂不确定是否需要数据库服务。

资料库使用完整真实数据确定资料边界、文件类型和 JSON Schema，自动资料通过脚本整体同步。
首版 Prompt 上下文已经实现，后续根据试写结果调整字段。

## 3. 文件类型与内容边界

### 3.1 院系资料：Markdown

- 每个院系一个文档，院系清单以现有 `teams.json` 为准。
- 文档包含男足、女足、五人制三支队伍的描述；没有对应队伍时写“无”。
- 文档包含 25-26 赛季该院系全部报名球员的描述。
- 每支球队和每名球员均只有一段人工维护的描述字符串。
- 球员在院系内以姓名识别，完整定位为“院系 + 姓名”；院系内重名交由人工处理。
- 描述可以包含风格、年级、位置、伤病等人工信息，不重复系统能够取得的比赛统计。

院系文档按“球队/球员”二级标题和球队类型或“姓名（球队类型）”三级标题解析。

### 3.2 自动资料：JSON

用于保存系统能够取得的赛事、比赛、比分、事件、排名和球员比赛数据。只使用经过安全映射
的字段，不保存手机号、证件信息或未经筛选的完整接口响应。

一旦选择某个实体作为 Schema 样例，就必须完整保存其安全映射字段。比赛详情不得只保留
进球和牌，而应包含首发、换上、换下等全部返回事件。首批完整样例使用
`schema_version: 1`；后续字段调整必须同步修改样例和版本说明。

赛事与比赛分别保存，`manifest.json` 记录每届赛事和整套快照的数量及完整性。当前通过
`scripts/sync_ai_preview_automatic.py` 使用自动凭据整体重建 23-24、24-25、25-26 三个赛季
共 14 届赛事；只有全部比赛详情读取成功后才写入。首版 Prompt 汇总方式已经实现，长期刷新
时机仍待实际使用后确定。

### 3.3 语料和规则：Markdown

- 一场比赛对应一个 `<MATCH_ID>.md`；同一篇推送包含多场比赛时拆分保存。
- 文档只保留该场“比赛前瞻”的正文，不保存天气、赛程、历史数据、当届战绩、署名、链接
  等推送中的其他内容。
- 没有独立前瞻正文的比赛不建立空文件。
- 暂不按写作风格分类。
- `src/ai_preview/prompt/writing_rules.md` 用于整理可直接提供给作者或 AI 的正文内容、写作
  原则、行文风格和禁用表达。
- `src/ai_preview/prompt/data_rules.md` 用于解释 Prompt 中人工资料、自动资料、统计口径和
  事件结构，并规定资料冲突、缺失和主客转换的处理方式。
- `src/ai_preview/prompt/system.md` 保存 System message 的单句写作宗旨；实际请求按
  `system.md`、本场项目对应的赛制说明、`writing_rules.md`、`data_rules.md` 的顺序组装
  System message。
- 是否建立 JSON 索引以及索引字段，等语料数量和使用方式明确后决定。

## 4. 实施顺序

### 阶段一：搭建并填充本地资料库

1. 确认目录和院系文档样例。
2. 根据 `teams.json` 建立院系文档骨架。
3. 整理 25-26 赛季报名球员并归入院系文档。
4. 逐步人工填写球队和球员描述。
5. 保存近三个赛季全部 14 届赛事的完整赛事、比赛和球员自动数据。
6. 收集优秀前瞻并初步整理通用规则。
7. 根据实际资料修订文件结构，完成资料库阶段检查。

阶段检查重点是：现有球队和报名球员能够被表达和定位；人工内容与自动内容边界清楚；
若干真实比赛所需资料能够从本地文件中找到；入选样例不能丢失安全模型中的字段或事件。
整体资料覆盖率暂不设置精确指标。

### 阶段二：Prompt 工程和验收

首版 Prompt 使用固定 System 规则和按 `MATCH_ID` 组装的 User message。使用约 5-10 场比赛
进行本地试写和人工验收，记录问题后迭代上下文字段与规则。

### 阶段三：网站接入

本地资料维护和生成效果得到初步验证后，再讨论网站中的维护入口、生成入口和人工发布流程。

## 5. 当前暂不确定的事项

- 自动数据的长期刷新时机和历史版本保留策略；
- 是否还需要近三个赛季快照之外的其他自动数据类型；
- 上下文组装字段在试写后的调整；
- 示例选择、事实引用和模型输出形式；
- 生成记录的目录与保存内容；
- 未来是否导入 SQLite、网站数据库或继续直接读取文件。

这些事项在资料库搭建过程中根据真实数据和维护体验逐项确定。
