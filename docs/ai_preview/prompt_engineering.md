# AI 前瞻 Prompt：要求与验收框架

## 1. 当前状态

Prompt 工程在本地资料库搭建完成后开始。现阶段不确定具体 Prompt 模板、消息分层、上下文
拼装方式、示例数量或输出 Schema，只记录生成时必须满足的要求和初步验收方法。

语料暂不区分写作风格，先整理一套通用规则。

## 2. 主要输入

- 人工球队描述；
- 人工球员描述；
- 系统能够取得的赛事、赛程、赛果、排名和比赛事件；
- 优秀历史前瞻与人工总结的写作规则；
- 本次比赛的额外人工说明。

具体选择哪些资料、如何裁剪上下文以及冲突时如何呈现，等资料库样例完成后再设计。

## 3. 主要生成目标

需要支持：

- 单场或一批比赛的前瞻正文草稿；
- 前瞻文章的标题候选；
- 供人工检查的资料缺失或冲突提示。

正文和标题使用一个 Prompt 还是分别生成、输出纯文本还是结构化数据，目前不作决定。

## 4. 核心要求

1. **事实忠实**：不得创造比分、战绩、球员特点、伤病、阵容或历史经历。
2. **资料边界清楚**：人工描述与自动比赛数据各司其职；语料只用于总结写法，不能成为本场事实。
3. **缺失时降级**：资料不足时减少具体判断，不使用模型记忆补全。
4. **身份正确**：球员必须结合院系和姓名定位，不能只凭同名跨球队或跨赛季关联。
5. **表达平衡**：无依据时不偏向任何一方，不作确定性胜负预测。
6. **可编辑**：文章结构清楚、语言自然，能够由编辑继续修改。
7. **人工确认**：生成内容只作为草稿，不自动发布。

是否要求逐句事实引用、如何报告冲突以及如何限制文章长度，留到 Prompt 设计阶段验证。

## 5. 通用写作要求初稿

- 使用简体中文，称呼、比分、日期和比赛阶段保持一致。
- 围绕双方现状、已有资料和对阵看点展开，避免无关的励志内容和空话。
- 球队打法、球员角色和历史标签必须有资料支持。
- 不使用“必胜”“毫无悬念”“碾压”等确定性或夸张预测。
- 资料较少时缩短文章，不用重复表达填充篇幅。
- 标题应与整篇前瞻覆盖的比赛范围一致，不能为追求效果虚构事实。

这些要求会在语料整理和首轮试写后继续修改，暂不固化为 Prompt 模板。

## 6. 初步验收

资料库完成后，选择约 5-10 场比赛进行人工评测。样本尽量包含不同赛事类型、不同比赛
阶段，以及人工资料完整、部分缺失和明显不足的情况；也可加入同名球员或资料冲突样例。

首轮重点观察：

- 是否出现事实虚构、数字错误或球员归属错误；
- 是否正确使用球队和球员描述；
- 资料不足时是否克制并提示缺项；
- 双方叙述是否基本平衡；
- 正文和标题是否自然、清楚、便于人工编辑；
- 人工需要进行哪些修改。

现阶段不设置统一分数、精确通过比例或严格长度指标。首轮评测的目的主要是暴露问题，
并帮助确定后续 Prompt 组织逻辑。

## 7. Prompt 阶段再决定的事项

- 正文和标题是否拆分生成；
- 系统指令、规则、示例和比赛资料的组织顺序；
- Markdown、XML 或 JSON 等上下文表达方式；
- 是否使用结构化输出及其字段；
- 是否建立事实引用或自动校验机制；
- 示例选择、上下文长度、模型和参数；
- 版本记录与对比评测方式。
