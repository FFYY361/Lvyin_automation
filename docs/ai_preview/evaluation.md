# AI 前瞻写作测试方案

## 1. 测试目标

本测试用于比较不同模型、模型配置和 Prompt 版本生成马杯前瞻正文的质量，并据此发现资料、
Prompt 和生成服务中的问题。首轮测试重在定位问题和形成可重复的人工判断方法，不设置固定
通过分数。

测试对象是模型未经人工修改的首次完整输出。评分时以该次请求实际收到的 System message 和
User message 为事实边界：即使某个说法在现实中正确，只要输入资料没有提供，也视为无依据。

`data/ai_preview/corpus/<MATCH_ID>.md` 中的已发表前瞻可以帮助评审理解选材和行文，但不是标准
答案。语料可能使用了 Prompt 未提供的编辑部信息，决赛文章也可能采用当前写作规则不允许的
特殊结构或真实姓名，因此不能要求模型仿写或逐项覆盖。

## 2. 测试方法

同一轮比较应固定本地资料快照、Prompt 代码与配置，只改变待比较的模型或明确记录的生成
参数。首轮每个“模型 × 比赛”生成一篇；若两个候选模型表现接近，再对关键场次重复生成，
观察稳定性。

每次生成至少记录：

- `MATCH_ID`；
- 模型 profile、实际模型名和生成时间；
- Prompt 所在 Git commit，以及 `recent_matches_with_events`、`history_seasons`；
- 温度、最大输出 Tokens 等模型参数；
- 原始输出、红线问题、各项得分、主要问题和必要修改。

横向比较时隐藏模型名称，先完成独立评分再查看模型信息。事实核对以本次组装出的 Prompt 为准，
并特别检查目标比赛之后的信息是否被误用。评分完成前不参考该场已发表语料，以减少锚定影响。

## 3. 红线检查

出现下列任一问题，将该篇标记为“不可直接使用”。仍然完成后续评分，保留问题分布用于改进，
但不因总分较高而忽略红线：

1. 写错比赛项目、级别、阶段、对阵双方或正文主客顺序；
2. 泄露目标比赛赛果，或把目标比赛之后才发生的结果写入赛前文章；
3. 编造或严重张冠李戴比分、排名、交锋、球员特点、伤病、位置等关键事实；
4. 出现球员、教练、裁判等个人真实姓名；
5. 贬低、羞辱或歧视球队和个人，或使用“必胜”“毫无悬念”等确定性赛果表述；
6. 没有生成一篇完整正文，例如只给提纲、说明、拒答或大段元话语。

轻微措辞不准、局部重复和普通结构问题不列为红线，在分项评分和修改记录中体现。

## 4. 评分标准

总分为 100 分，由五个维度组成。每个维度先按 `0-5` 分评分，可以使用 `0.5` 分，再乘以该
维度系数。通用含义如下：

- `5`：充分满足要求，基本只需校对；
- `4`：整体良好，有少量局部修改；
- `3`：基本可用，但存在清晰可见的问题；
- `2`：问题较多，需要改写多个句子或局部段落；
- `1`：大部分内容不能沿用，需要重写；
- `0`：没有完成该维度的基本任务。

### 4.1 事实与资料遵循：35 分

维度分乘以 `7`。

检查内容：

- 本场赛事、阶段、主客顺序、时间和场地等信息是否准确；
- 战绩、排名、比分、交锋和人员信息是否与输入一致，球队归属是否正确；
- 是否正确理解点球大战、判定胜负、空数组、`null` 和“待补充”；
- 是否把主客相反的历史交锋正确转换为本场视角；
- 是否区分事实、判断和展望，没有补写资料不支持的阵型、伤病、位置或因果关系；
- 是否只使用目标比赛之前的信息，没有从本场赛果或后续比赛倒推赛前状态。

`5` 分要求没有可识别的事实错误或无依据断言；`3` 分表示核心比赛信息正确，但有一两处局部
误读或不严谨推断；`0-1` 分表示核心对象错误、存在多处编造，或文章无法进行可靠事实核对。

### 4.2 内容结构与双方平衡：20 分

维度分乘以 `4`。

检查内容：

- 正文是否恰好三段，依次介绍主队、客队并在第三段综合收束；
- 前两段是否都有具体内容，篇幅和评价尺度是否大致均衡；
- 每段是否围绕本场有明确重点，而不是资料的无序拼接；
- 第三段是否承接前两段写出真实的对位、目标或悬念，而不是通用结尾。

`5` 分表示三段各司其职且形成完整论述；`3` 分表示结构正确但双方失衡、段落重点松散或第三段
较模板化；`0-1` 分表示顺序和段落任务大面积错误。

### 4.3 选材与比赛分析：20 分

维度分乘以 `4`。

检查内容：

- 是否从人工描述、当前赛事、近期比赛和历史记录中选择最能说明本场的信息；
- 是否把比分和统计组织成状态判断，避免流水账式罗列；
- 是否写出有依据的风格对位、阵容处境、晋级目标或再度交锋背景；
- 是否知道取舍，资料不足时保持克制，资料丰富时不贪多；
- 是否避免同一事实反复出现，或把全部首发、进球和事件机械复述。

`5` 分表示选材精准，分析具体且紧扣本场；`3` 分表示使用了一些有效资料，但仍以复述为主或
看点较泛；`0-1` 分表示几乎没有使用有效资料，或分析主要依靠空话和猜测。

### 4.4 行文与风格：15 分

维度分乘以 `3`。

检查内容：

- 语句是否通顺，段内逻辑和段间衔接是否自然；
- 词汇、句式和节奏是否有变化，是否存在明显重复和万能套话；
- 是否具有校园体育报道的感染力，同时保持克制；
- 比喻、延伸和设问是否服务于比赛内容，是否出现通篇辞藻堆砌；
- 开头和结尾是否自然，是否有明显模板痕迹。

`5` 分表示准确、流畅、具体且有适度文采；`3` 分表示可读但较平、存在套话或局部用力过度；
`0-1` 分表示表达混乱、机械重复或修辞严重遮蔽事实。

### 4.5 写作规范与修改成本：10 分

维度分乘以 `2`。

检查内容：

- 是否尊重双方，保持一致评价尺度，不把一方写成另一方的陪衬；
- 是否用赛前措辞表达判断，没有把预测写成确定结果；
- 是否完全避免真实姓名、无依据绰号、贬损和不合适的暴力表达；
- 编辑能否在不重新查资料、不重构全文的情况下完成修改。

`5` 分表示只需字词校对即可进入编辑流程；`3` 分表示需要若干明确的内容和措辞修改，但主体
可以保留；`0-1` 分表示存在红线或需要重写大部分文章。

总分计算公式：

```text
总分 = 事实与资料遵循 × 7
     + 内容结构与双方平衡 × 4
     + 选材与比赛分析 × 4
     + 行文与风格 × 3
     + 写作规范与修改成本 × 2
```

初轮不划定合格线。比较时优先查看红线数量、事实与资料遵循、平均总分和不同类型比赛上的
稳定性，不能只按总分排序。

## 5. 测试集

测试集共 8 场，均为 25-26 赛季。表中的对阵严格使用比赛快照的主队在前顺序；每场现有
`corpus/<MATCH_ID>.md` 可在评分完成后作为编辑参考。

| 序号 | MATCH_ID | 项目与阶段 | Prompt 主客顺序 | 主要覆盖点 |
| --- | ---: | --- | --- | --- |
| 1 | 4237 | 男足乙级决赛 | 求真 vs 新雅 | 决赛氛围、升级目标、完整赛季资料和双方均衡 |
| 2 | 4246 | 女足决赛 | 经管-地研 vs 医药卫健 | 与小组赛再次交锋、历史主客转换、淘汰赛收束 |
| 3 | 4245 | 男足甲级决赛 | 车辆 vs 未央 | 资料较丰富时的取舍、强强对话和修辞克制 |
| 4 | 4065 | 女足 D 组第 2 轮 | 医药卫健 vs 经管-地研 | 早期赛事资料、赛前时间截断、不得泄露后续决赛 |
| 5 | 4024 | 男足乙级 E 组第 2 轮 | 交叉-AI vs 人文 | 非决赛常规前瞻、资料差异下的平衡和具体分析 |
| 6 | 4049 | 男足丙级 L 组第 2 轮 | 日新 vs 集电 | 资料较少时的克制、避免空话和事实补写 |
| 7 | 4076 | 女足 B 组第 1 轮 | 日新 vs 电子 | 首轮无本届战绩时的选材、跨赛季资料使用 |
| 8 | 4011 | 男足乙级 E 组第 3 轮 | 航院-航发院 vs 交叉-AI | 小组后段形势、当前排名与战绩的取舍、同队跨轮次稳定性 |

这组比赛同时覆盖男足甲、乙、丙三级和女足，包含决赛、小组赛首轮至第三轮、丰富资料与稀疏
资料、重复对阵和历史主客相反等情况，并可比较交叉男足在不同轮次前瞻中的叙述稳定性，
可以作为首轮 Prompt 与模型比较的固定集合。
