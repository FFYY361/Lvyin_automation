# 自动化比赛前瞻工具实现计划

## 目标

实现一条最小可用管线：输入日期，读取当日比赛和基础历史数据，套用既有公众号模板，并把每场前瞻提交到公众号草稿箱。

## 当前实现范围

- 单一 THUFootball 数据源、单一公众号账号、单一模板。
- 模板来源先支持一个可正常访问的已发表文章 URL。
- 任一步骤失败即停止并输出错误；暂不处理复杂重试、断点恢复和多账号并发。
- 自动化终点为草稿箱，不实现自动发布。

## 主要能力

| 序号 | 能力 | 最小实现内容 | 完成标志 |
| --- | --- | --- | --- |
| 1 | 项目骨架与配置 | 建立配置读取、密钥环境变量、日志和基础数据类型 | 程序可启动并验证必要配置 |
| 2 | THUFootball 客户端 | 封装鉴权及 `GetCurrentGames`、`GetGameInfo`、`GetTournInfo` | 可按参数取得并解析接口响应 |
| 3 | 指定日期比赛读取 | 按上海时区筛选某自然日比赛，生成统一比赛对象 | 输入日期后输出当日比赛列表 |
| 4 | 历史战绩整理 | 筛选两队此前比赛、双方交锋，计算最近 N 场胜平负和进失球 | 每场比赛可输出结构化前瞻数据 JSON |
| 5 | 已发表文章提取 | 从指定文章取得正文 HTML、标题和图片引用，移除无关页面内容 | 可保存一份干净的本地 HTML 样本 |
| 6 | 模板化与内容填充 | 把动态区域改为显式占位符，用比赛数据和编辑文案渲染新文章 | 可在本地生成一份完整前瞻 HTML |
| 7 | 公众号媒体与草稿接口 | 获取访问凭据，上传正文图片/封面，替换地址并新增草稿 | 可用最小文章创建一个测试草稿 |
| 8 | 管线编排与预演 | 串联日期查询、数据整理、模板渲染和草稿提交，提供 `dry-run` | `dry-run` 只产出文件，正式模式产出草稿标识 |

## 推荐实现顺序

1. 完成能力 1–4，以结构化 JSON 作为第一个里程碑。
2. 完成能力 5–6，以本地 HTML 预览作为第二个里程碑。
3. 单独完成能力 7，用固定最小文章验证草稿写入。
4. 完成能力 8，先跑 `dry-run`，确认结果后再启用真实草稿提交。

## 建议输出结构

```text
output/{date}/games.json
output/{date}/{game_id}/data.json
output/{date}/{game_id}/article.html
output/{date}/{game_id}/run.json
```

## 最小验收标准

- 给定一个有比赛的日期，可以稳定得到比赛列表及每场的基础历史数据。
- 给定一个已配置模板，可以为每场比赛生成可人工预览的 HTML。
- 同一份 HTML 完成图片处理后，可以进入公众号草稿箱。
- 每次运行保留比赛 ID、模板版本、执行结果和草稿标识，且日志不包含密钥。
